# Bring-up on MI450 A0 (gfx1250, single GPU)

Running the yambda-5b HSTU ranker on an **MI450 A0 engineering sample**. The
stack works — fbgemm builds, TorchRec shards, the 4.76B-event dataset streams,
the benchmark reaches `run_stop` — but **training does not survive**: the loss
goes `nan`. Best known configuration trains correctly for ~2150 steps (~12 min),
loss decreasing and matching the PyTorch reference, then poisons:

```bash
IMG=recommendation-amdprimus0815:triton-3.7.1-amd   # Triton 3.7.1, AMD build
AMDGCN_USE_BUFFER_OPS=0                             # default in the runner
./scripts/run_smoke_shrink_1gpu.sh
```

Branch `chcai/mi450_a0`. Companion to [`training_recipe.md`](./training_recipe.md)
and [`perf_opt.md`](./perf_opt.md).

## Everything known about the open problems

All are in the Triton path; none is in the benchmark's math. Rows 1 and 2 are
ready to hand to the Triton team as-is; row 3 is the blocker. Only the Triton
wheel was ever swapped (`--no-deps`), holding torch, ROCm and driver constant.

## The node

1× MI450 A0 engineering sample, `gfx1250`, PCI `1002:75c1`, SKU `M4500001`, rev
`0x00` — 256 WGPs, ~432 GiB HBM, **`warp_size=32`** (RDNA, not CDNA wave64).
ROCm 7.14, torch `2.11.0+rocm7.14.0a20260625`, Triton 3.6.0 stock. Host Linux
`6.14.0-37-generic`, amdgpu DKMS 7.1.1, Docker 29.6.1.

Two facts drive every change here: **one GPU** (the whole model must fit in one
HBM) and **wave32** (CDNA assumptions in fbgemm are wrong).

`amdgpu` is blacklisted by the kernel cmdline
(`modprobe.blacklist=amdgpu,device_dax,dax_hmem`), so after every boot run
`sudo modprobe amdgpu` — `/dev/kfd` appears ~15 s later.

**Recovery from a hang is a reboot.** The process sticks in uninterruptible `D`
state, `docker kill` returns *"did not receive an exit event"*, MODE2 reset fails
with `error code -62`, and `modprobe -r amdgpu` deadlocks. The wedge is
whole-device and survives container teardown: `rocm-smi` still answers while
holding VRAM with no processes alive, and a bare 1024² bf16 matmul in a fresh
container never returns. Untried: `flr`/`bus` reset and the `umr` wave debugger.

## Getting it to run

**Image** — [`Dockerfile.amdprimus0815`](../Dockerfile.amdprimus0815). Stock
`rocm/primus:v26.3` torch has no gfx1250 code objects, so *any* kernel fails with
`CUDA error: device kernel image is invalid`. `amdprimus/amdprimus:0815` has
gfx1250 torch but no fbgemm/torchrec, so those are built on top (~8 min). ROCm
lives in the wheel at `site-packages/_rocm_sdk_devel`, not `/opt/rocm`, so
`ROCM_HOME`/`HIP_ROOT_DIR` must point there or configure dies with
`BUILD_ROCM_VERSION is not set`. Also needs `libtbb-dev`, `libnuma-dev`,
`libssl-dev`, `ninja-build`.

**Three fbgemm patches** — (1) `Fbgemm.cmake` omits `FbgemmFloat16Convert*.cc` /
`FbgemmBfloat16Convert*.cc`, relying on torch's bundled FBGEMM; (2) host/device
**warp-size disagreement**, host assumed wave64; (3) codegen also hardcodes
wave64. With these, TBE is **bit-exact** against CPU.

**Embedding shrink** — `EMBEDDING_ROW_SCALE`; the reference tables are ~559 GiB
of fp32 weights against one ~432 GiB GPU.

**Dataset** — use the **MLCommons prepared download** (README Option A): 227.41
GB, 19 files, all md5/sha256 verified. Do **not** self-preprocess; the cache build
needs ~190 GB RAM and OOM-killed this 251 GB box.

## Performance

Triton 3.7.1, gin-default depth 3, `MAX_SEQ_LEN=4096`, `EMBEDDING_ROW_SCALE=0.25`,
`BATCH_SIZE=128`, buffer ops off — measured in the finite region, while the loss
was still converging. Step 50 is warmup (1920 ms, carrying compile and autotune).
Steady state is **~322 ms/step, ~395 samples/s, `tflops_real` 35–61, HFU
1.1–1.9%**. HFU tracks `fill` (29–49%) rather than being a fixed number, because
`fill` is the fraction of the dense-equivalent work the jagged batch actually
contains.

**Read `hfu`, not `mfu`.** `num_flops_per_sample` is a *static dense* estimate
(315.7 GFLOP/sample at 3 layers) while jagged attention performs only the `fill`
fraction of it, so `mfu` (3.7–4.2%) describes work that is never executed.
`tflops_real` is the honest count and `hfu` its utilization.

HFU is against **3150 TFLOP/s = 90% of the 3500 TFLOPS dense BF16 matrix peak**
for MI450. Two notes on that denominator. `get_gpu_peak_flops` matched nothing and
silently fell back to **MI350X's 2300 TFLOPS**, because these parts report the
generic name `AMD Radeon Graphics`, so every earlier perf line in this repo's logs
is normalized against the wrong chip; it is now keyed on `gcnArchName`. And the
silicon peak is used deliberately, not the ~75 TFLOP/s (~2% of it) this node can
actually reach today: measured bf16 GEMM is only **1.46× fp32** (67.8 vs 46.5 TF
at N=8192), i.e. the **matrix cores are idle** and everything runs on the vector
path at ~1.1 GHz against a 2.4 GHz max clock. Normalizing against measured
throughput would conflate model efficiency with BLAS immaturity and would
silently change meaning as kernels improve.

## Retracted

`and`/`or` on tensors is **not** a bug, and the `triton_position.py` rewrite was
cosmetic. Triton warns `Logical operators 'and' and 'or' are deprecated for
non-scalar tensors`, but `code_generator.py:visit_BoolOp` (3.6.0) lowers them to
`logical_and`/`logical_or`, which for boolean masks is exactly `&`/`|`. Nothing
goes unmasked. The position test passing afterwards was nondeterminism.

Separately, `hstu_compute::test_compute_output` was an **inherited code bug, not a
GPU bug**: the forward dropped `mul_u_activation_type`, so it applied no
activation while its own backward applied one. A one-line fix takes that parameter
grid from 32 mismatches to 0. Our file is byte-identical to
`mlcommons/training@master`, and the defect is dormant in the benchmark, which
only ever passes `"none"`.

## Change inventory

- `Dockerfile.amdprimus0815` — gfx1250 image: gfx1250 torch plus fbgemm built from
  source with the three wave32 patches.
- `scripts/run_smoke_shrink_1gpu.sh` — defaults `AMDGCN_USE_BUFFER_OPS=0` and
  `HSA_ENABLE_COREDUMP=0`; forwards `DEBUG_NAN_HOOKS`; `IMG` selects the image.
- `scripts/repro_gfx1250_buffer_ops.py` — standalone hang reproducer, torch+triton
  only.
- `scripts/build_triton_from_source.sh` — builds Triton at any `TRITON_COMMIT`,
  same recipe as sglang's Dockerfile.
- `dlrm_v4/utils.py` — peak-FLOPS table keyed on `gcnArchName` for gfx1250, so HFU
  stops using MI350X's number.
- `dlrm_v4/train/train_ranker.py` — `DEBUG_NAN_HOOKS` non-finite forward/backward
  hooks (diagnostic for row 3).
- `ops/triton/triton_hstu_linear.py` — upstream bug fix: forward now passes
  `mul_u_activation_type`.
- `ops/triton/triton_position.py` — cosmetic: `&` instead of `and`, silencing
  Triton's deprecation warning.
