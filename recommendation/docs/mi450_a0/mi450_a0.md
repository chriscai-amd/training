### Confirmed CWSR mechanism and correction

The faulty sequence is at `L_NOT_WAVE_START` in
`amd/amdkfd/cwsr_trap_handler_gfx12.asm`. It saves encoded `v1` through the
inherited SRC0 bank, temporarily writes `v1` through the destination bank,
then restores through that destination bank. When the banks differ, lane 0
is copied between physical registers. In the retained DW kernel, setter
`0x05` copies `v257[0] -> v1[0]` into an accumulator, `0x81` copies
`v257[0] -> v513[0]` into a matrix operand, and `0x46` copies
`v513[0] -> v257[0]` into a persistent X address. These setter encodings
are distinct from the raw MODE bank byte used in other tests.

The [source patch](cwsr_gfx1250_bank_fix.patch) saves and clears the six
DST/SRC0/SRC1 bank bits before touching `v1`, then restores them after
restoring `v1`. It preserves the intended prefetch and other MODE fields.
The partial MODE write uses `S_SETREG_B32`: the earlier immediate-write
proposal was withdrawn because of the documented masked-immediate erratum.
The reconstructed handler is 5,672 bytes, SHA256
`68c31ab204bdfe99551213b1716fb8b9944cd0fc315adb0b7ea8d9661e398b80`.
The baseline reconstruction matches all 5,656 installed handler bytes.
Regenerating the embedded handler array is required in addition to applying
the source patch; original SP3-assembler acceptance has not been tested.
[Detailed defect, native evidence and build procedure](cwsr_bank_corruption_fix.md).

Ordinary execution of the faulty prologue independently produces exactly
1,536 predicted copies across its 2,048 cases; the corrected and no-prologue
arms preserve every tag across another 4,096 cases. Fresh no-injection
probes and AutoNUMA stack/policy counterfactuals connect this mechanism to
spontaneous exposure. The seven-event DW replay reproduces every retained
historical output byte, and changing one DY bit changes the same corruption
from NaNs to finite errors. These results explain both tiny zero-gradient
violations and enormous/NaN DW values without treating every small alarm
as an exact reconstruction of the original training event.

### Plain-pointer API port and numerical guard

<a id="63-triton-language-api-port-5"></a>

Upstream removed `tl.make_block_ptr` and `tl.advance`. The implemented port
uses **masked plain-pointer loads/stores**; `_should_enable_tma()` remained
false on HIP. It did not enable Hopper TMA or an AMD descriptor lowering.
The mapping below is retained as a review aid; address products must use a
wide enough integer type, as row15 demonstrates.

| Before (Triton ≤ 3.8 AMD SDK) | After (this branch; compiles on `main`) |
|---|---|
| `tl.make_block_ptr(base=X, shape=(N, D), strides=(stride_x, 1), offsets=(start_row, 0), block_shape=(BLOCK_N, BLOCK_D), order=(1, 0))` | `rows = start_row + tl.arange(0, BLOCK_N)` and `cols = tl.arange(0, BLOCK_D)` |
| `tl.load(ptr, boundary_check=(0, 1), padding_option="zero")` | `tl.load(X + rows[:, None] * stride_x + cols[None, :], mask=(rows < N)[:, None] & (cols < D)[None, :], other=0.0)` |
| `tl.store(ptr, y, boundary_check=(0, 1))` | `tl.store(Y + rows[:, None] * stride_y + cols[None, :], y, mask=…)` |
| `ptr = tl.advance(ptr, (0, BLOCK_N))` (attention K/V tiles) | rebuild the pointer from the physical sequence offset each tile: `K + offset_kh + (seq_start + load_offs_n)[:, None] * stride_kn + …` — there is no longer a cursor to advance |


The port covered **26 `make_block_ptr` and eight `advance` call sites** in
`ops/triton/triton_hstu_attention.py`, `triton_layer_norm.py`, and
`triton_hstu_linear.py`. Jagged concat/split, position and addmm already used
plain pointers or an unused descriptor path. Physical sequence offsets belong
in K/V addresses; remapped `pos_offs_*` belong only in causal/contextual/
multi-target masks. Mixing them silently changes the layout.

Eight deterministic BF16 cases passed forward and backward at `atol=1e-5`,
`rtol=0.016` on `7ff97e3109` and AMD `3.8.0+git4cff872c`, using
[`scripts/attn_check.py`](../../scripts/attn_check.py). These fixed-shape,
single-shot checks passed even while the varying-layout attention-backward
fault remained. Preserve both numerical checks and repeated layout coverage
when replacing this port. Full compatibility notes and historical invocation
are in [historical §6.3](history_8377ae9.md#63-triton-language-api-port-5).
