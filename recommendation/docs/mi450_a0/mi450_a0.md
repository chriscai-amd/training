## Where the enormous value first appears

Attempt 405 captures X `[2324351,256]`, maximum `0.0048828125`, and DY
`[2324351,512]`, maximum `0.000885009765625`. Both are finite and their complete
pre/post backing bytes match. Raw DW `[256,512]`, stride `[1,256]`, contains
the corrupt block `[0:8,128:256]`. DX/DB and retained top-layer projection
inputs/outputs remain finite.

The expected transpose and BF16→FP32 conversion, leaf gradient, accumulated
gradient, backward-return gradient and final selected dense gradient are
**bit-exact**, including the NaNs. This is before clipping and the explicit
optimizer step; in-backward sparse updates may already have occurred.

At one captured `+7.9723e29` coordinate, an exact-integer sum of all 2,324,351
BF16 products is **`-4.1748697645262154e-7`**. The exact-real global magnitude
bound is 10.0443; a conservative ordinary FP32 accumulation bound is 13.8942.
Ordinary accumulation overflow cannot explain this event under that model.

The historical `1e37`–`1e38` events are still unlinked. B0's captured layer
norm and jagged split receive already-enormous inputs; they establish
propagation, not the original producer. A0's earlier step-380 GEMM similarly
receives bad DOut before executing. The attempt-405 raw-DW capture is a newer,
stronger producing interval, not proof that every earlier event shares it.

Primary raw-DW evidence: [complete attempt-405 CPU audit](evidence/current_20260919/training405_full_payload.json)
and [isolated call-196 CPU audit](evidence/current_20260919/single_DW196_full_failure.json).
The retained X-row/common-scalar donor search excludes that specific model
for the wrong replay columns. It does not exclude multirow sums, remapping
or changed intermediate arithmetic.

A separate [training-DY row search](evidence/current_20260919/training405_DY_row_scalar_search.json)
tests each of the three huge finite DW row slices, M=0,1,5 and N128:256,
against every one of the 2,324,351 original DY rows. None has the necessary
sign pattern for multiplication by a scalar of either sign. An
[independent complete-vector scan](evidence/current_20260919/training405_DY_row_scalar_independent.json)
confirms this rejection. The other five affected rows contain 640 `0xffc0`
NaNs and are outside this finite-scalar model. This excludes only one saved
DY row times one finite real scalar for each tested slice; it assigns no

[bounded-residual extension](evidence/current_20260919/training405_DY_row_bounded_residual.json)
with an [independent exact bound review](evidence/current_20260919/training405_residual_bound_review.json)
also allows arbitrary coordinate residuals up to the absolute sum bound for
the other K−1 original terms: **10.0442991**. Every target rounding interval
lies more than `6.2e27` from zero, so those residuals cannot change the necessary
signs. This also rejects one changed X coefficient plus an otherwise exact
real contraction and final BF16-RNE cast. Intermediate arithmetic faults and
other rounding models remain outside this result.

A [rank test](evidence/current_20260919/training405_shared_two_rows_rank.json)
also rejects two shared DY rows with independent coefficients for each of the
three finite output rows, allowing the same residual bound. For M=0,1,5 and

each output row, remapping or unbounded intermediate arithmetic errors.

depth or width. Both setups retain three HSTU layers, width 512, four heads,
sequence limit 4096 and local batch 1024. Quarter scaling has **73,262,927
rows**. Source and installed TorchRec inspection establish these effects:

- Base IDs wrap modulo the smaller vocabulary and cross-feature hashes use
  smaller capacities, changing collisions and sparse update frequency.
- Fused TorchRec actually initializes shards with bounds
  `±sqrt(1/num_embeddings)`. Quarter rows therefore give approximately
  **2× initial amplitude / 4× variance**. This is confirmed in the installed
  fused initialization path, not inferred only from the eager `init_fn`.
- Allocation size, shard placement, random-number consumption and sparse
  execution can also change. Row scaling itself does not change history
  selection or labels, so dense shapes should match at fixed batching.

The existing cross-host comparison also changes global batch 1024→4096,
sample/rank assignment and eligible windows, sharding and communication,
allocator settings, driver/kernel/firmware, and observation. Both 1P4G
launchers clear the expandable-segment allocator setting used by A0.

B0 reports **650D**. These are additional recorded differences, not a firmware

### Plain-pointer API port and numerical guard

<a id="63-triton-language-api-port-5"></a>

Upstream removed `tl.make_block_ptr` and `tl.advance`. The implemented port
uses **masked plain-pointer loads/stores**; `_should_enable_tma()` remained
false on HIP. It did not enable Hopper TMA or an AMD descriptor lowering.
The mapping below is retained as a review aid; address products must use a
wide enough integer type, as row15 demonstrates.

| Before (Triton ≤ 3.8 AMD SDK) | After (this branch; compiles on `main`) |
|---|---|
| `tl.make_block_ptr(base=X, shape=(N, D), strides=(stride_x, 1), offsets=(start_row, 0), block_shape=(BLOCK_N, BLOCK_D), order=(1, 0))` | `rows = start_row + tl.arange(0, BLOCK_N)` and `cols = tl.arange(0, BLOCK_D)` |
| `tl.load(ptr, boundary_check=(0, 1), padding_option="zero")` | `tl.load(X + rows[:, None] * stride_x + cols[None, :], mask=(rows < N)[:, None] & (cols < D)[None, :], other=0.0)` |
| `tl.store(ptr, y, boundary_check=(0, 1))` | `tl.store(Y + rows[:, None] * stride_y + cols[None, :], y, mask=…)` |
| `ptr = tl.advance(ptr, (0, BLOCK_N))` (attention K/V tiles) | rebuild the pointer from the physical sequence offset each tile: `K + offset_kh + (seq_start + load_offs_n)[:, None] * stride_kn + …` — there is no longer a cursor to advance |


The port covered **26 `make_block_ptr` and eight `advance` call sites** in
`ops/triton/triton_hstu_attention.py`, `triton_layer_norm.py`, and
`triton_hstu_linear.py`. Jagged concat/split, position and addmm already used
plain pointers or an unused descriptor path. Physical sequence offsets belong
in K/V addresses; remapped `pos_offs_*` belong only in causal/contextual/
multi-target masks. Mixing them silently changes the layout.

Eight deterministic BF16 cases passed forward and backward at `atol=1e-5`,
`rtol=0.016` on `7ff97e3109` and AMD `3.8.0+git4cff872c`, using
[`scripts/attn_check.py`](../../scripts/attn_check.py). These fixed-shape,
single-shot checks passed even while the varying-layout attention-backward
fault remained. Preserve both numerical checks and repeated layout coverage
when replacing this port. Full compatibility notes and historical invocation
are in [historical §6.3](history_8377ae9.md#63-triton-language-api-port-5).
